# Проблема анимации вращения барабанов слот-машины

## Текущее поведение

При нажатии кнопки "СПИН" символы на барабанах начинают вращаться. Однако визуально это выглядит как **мелькание символов**, а не как вращение ленты. При остановке барабана все символы **резко меняются** на финальные.

## Причина проблемы

### Текущая архитектура

```
Количество символов на барабан: 5 (BUF=1, ROWS=3)
- 1 буферный символ сверху
- 3 видимых символа 
- 1 буферный символ снизу

Позиции (при BUF=1, H≈273):
- Символ 0: Y = -136 (буфер сверху)
- Символ 1: Y = 136 (видимый ряд 0)
- Символ 2: Y = 410 (видимый ряд 1)
- Символ 3: Y = 683 (видимый ряд 2)
- Символ 4: Y = 957 (буфер снизу)
```

### Как работает вращение

1. Каждый кадр символы сдвигаются вниз на `SPEED` пикселей
2. Когда символ выходит за нижнюю границу → переносится наверх + получает **случайную текстуру**
3. При остановке (`stop=true`) вызывается `fin()` → все видимые символы получают **финальные текстуры**

### Проблема

**Финальные символы НЕ являются частью ленты** — они просто подставляются в конце. 
Из-за этого:
- Во время вращения видны случайные символы
- При остановке происходит резкая замена на финальные символы
- Нет ощущения "докручивания" ленты до нужной позиции

## Как должно работать (реалистичный слот)

```
1. Лента содержит ~20+ символов в фиксированном порядке
2. При получении результата спина, финальные символы УЖЕ находятся на ленте
3. Вращение - это просто движение ленты
4. Остановка - лента тормозит и останавливается на нужных символах
5. Никакой замены текстур не происходит
```

## Возможные решения

### Решение 1: Минимальные изменения (визуальное улучшение)

Уменьшить размытие и скорость чтобы символы были видны при вращении.
Замена всё равно будет, но менее заметна из-за плавного перехода.

```typescript
private readonly SPEED = 25;      // было 35
private readonly MAX_BLUR = 4;    // было 20
```

**Плюсы**: Простая реализация, не ломает существующий код
**Минусы**: Не решает корневую проблему

### Решение 2: Полная переработка системы

Создать настоящую ленту символов:

```typescript
// Новые параметры
private readonly REEL_LENGTH = 20;  // Символов на ленте
private reelStrip: string[][] = []; // Порядок символов на каждом барабане

// При получении результата спина:
// 1. Вычислить какая позиция ленты даёт нужные финальные символы
// 2. Вращать ленту до этой позиции
// 3. Плавно затормозить

// Структура состояния:
private state: {
  on: boolean;
  currentPosition: number;  // Текущая позиция ленты (0 до REEL_LENGTH * H)
  targetPosition: number;   // Целевая позиция для остановки
  velocity: number;         // Текущая скорость
}[] = [];
```

**Плюсы**: Реалистичное поведение как в настоящих слотах
**Минусы**: Требует ~200 строк нового кода, время на отладку

### Решение 3: Гибридный подход

При получении сигнала остановки:
1. Вставить финальные символы в ленту (на позиции выше видимой области)
2. Докрутить ленту так, чтобы эти символы вошли в видимую область
3. Не менять текстуры в `fin()` — символы уже правильные

```typescript
private prepareStop(c: number) {
  // Найти спрайты выше видимой области
  // Назначить им финальные текстуры
  // Вычислить точку остановки
}
```

**Плюсы**: Компромисс между простотой и реалистичностью
**Минусы**: Сложная логика синхронизации позиций

## Текущие файлы

- `frontend/src/game/SlotMachine.ts` - основной класс слот-машины
- Ключевые методы:
  - `spin()` - запуск вращения
  - `runAnim()` - основной цикл анимации
  - `updReel(c)` - обновление позиций символов
  - `fin(c)` - финализация остановки барабана

## Рекомендация

Для полноценного решения проблемы рекомендуется **Решение 2** (полная переработка). 
Это потребует времени, но даст результат соответствующий ожиданиям.

Для быстрого визуального улучшения можно применить **Решение 1**.
